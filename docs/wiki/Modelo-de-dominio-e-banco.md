# Modelo de domínio e banco de dados

[← Início](Home.md)

## Hierarquia de entidades

```
BaseEntity (id)                    @MappedSuperclass
├── NamedEntity (name)             @MappedSuperclass
│   ├── Pet        → tabela pets
│   ├── PetType    → tabela types
│   └── Specialty  → tabela specialties
├── Person (firstName, lastName)   @MappedSuperclass
│   ├── Owner      → tabela owners
│   └── Vet        → tabela vets
└── Visit          → tabela visits
```

`@MappedSuperclass` diz ao JPA: "esta classe não é tabela, mas seus campos entram na tabela de cada subclasse". É herança da orientação a objetos virando colunas. Diagrama: [UML 02, classes do domínio](../uml/svg/02_classes_dominio.svg).

[BaseEntity.java](../../src/main/java/org/springframework/samples/petclinic/model/BaseEntity.java#L32-L51)

```java
@MappedSuperclass
public class BaseEntity implements Serializable {

	@Id
	@GeneratedValue(strategy = GenerationType.IDENTITY)
	private Integer id;

	public boolean isNew() {
		return this.id == null;
	}
}
```

`IDENTITY` deixa o banco gerar o id (`GENERATED BY DEFAULT AS IDENTITY` no PostgreSQL). `isNew()` é usado pelos formulários para decidir entre "criar" e "editar".

## Relacionamentos

[Owner.java](../../src/main/java/org/springframework/samples/petclinic/owner/Owner.java#L48-L70): um tutor tem muitos pets.

```java
@Entity
@Table(name = "owners")
public class Owner extends Person {

	@Column
	@NotBlank
	@Pattern(regexp = "\\d{10}", message = "{telephone.invalid}")
	private String telephone;

	@OneToMany(cascade = CascadeType.ALL, fetch = FetchType.EAGER)
	@JoinColumn(name = "owner_id")
	@OrderBy("name")
	private final List<Pet> pets = new ArrayList<>();
```

[Pet.java](../../src/main/java/org/springframework/samples/petclinic/owner/Pet.java#L44-L59): um pet tem um tipo e muitas visitas.

```java
@Entity
@Table(name = "pets")
public class Pet extends NamedEntity {

	@ManyToOne
	@JoinColumn(name = "type_id")
	private PetType type;

	@OneToMany(cascade = CascadeType.ALL, fetch = FetchType.EAGER)
	@JoinColumn(name = "pet_id")
	@OrderBy("date ASC")
	private final Set<Visit> visits = new LinkedHashSet<>();
```

[Vet.java](../../src/main/java/org/springframework/samples/petclinic/vet/Vet.java#L47-L50): muitos para muitos via tabela de junção.

```java
@ManyToMany(fetch = FetchType.EAGER)
@JoinTable(name = "vet_specialties", joinColumns = @JoinColumn(name = "vet_id"),
		inverseJoinColumns = @JoinColumn(name = "specialty_id"))
private Set<Specialty> specialties;
```

| Anotação | Significado | Efeito no banco |
|---|---|---|
| `@OneToMany` + `@JoinColumn` | um para muitos | coluna `owner_id` em `pets` |
| `@ManyToOne` | muitos para um | coluna `type_id` em `pets` |
| `@ManyToMany` + `@JoinTable` | muitos para muitos | tabela `vet_specialties` |
| `cascade = ALL` | salvar o pai salva os filhos | `save(owner)` grava pet e visita novos |
| `fetch = EAGER` | carrega junto | os pets vêm na mesma consulta do tutor |

Por causa do `cascade`, o `VisitController` grava uma visita salvando o tutor:

```java
owner.addVisit(petId, visit);
this.owners.save(owner);
```

## Validação

As restrições ficam na própria entidade (Bean Validation) e o controller só pede `@Valid`:

```java
@NotBlank
@Size(max = 255)
private String description;          // Visit

@Pattern(regexp = "\\d{10}", message = "{telephone.invalid}")
private String telephone;            // Owner
```

A mensagem `{telephone.invalid}` é traduzida pelos arquivos `messages_*.properties`.

## Repositórios e genéricos

O Spring Data gera a implementação a partir da interface. O tipo da entidade e o tipo do id são parâmetros genéricos.

[OwnerRepository.java](../../src/main/java/org/springframework/samples/petclinic/owner/OwnerRepository.java#L36-L62)

```java
public interface OwnerRepository extends JpaRepository<Owner, Integer> {

	Page<Owner> findByLastNameStartingWith(String lastName, Pageable pageable);

	Optional<Owner> findById(Integer id);

}
```

O nome `findByLastNameStartingWith` vira `WHERE last_name LIKE ?`. É a chamada **query derivada**: o SQL sai do nome do método.

[PetTypeRepository.java](../../src/main/java/org/springframework/samples/petclinic/owner/PetTypeRepository.java#L30-L39): consulta escrita à mão em JPQL.

```java
public interface PetTypeRepository extends JpaRepository<PetType, Integer> {

	@Query("SELECT ptype FROM PetType ptype ORDER BY ptype.name")
	List<PetType> findPetTypes();

}
```

[VetRepository.java](../../src/main/java/org/springframework/samples/petclinic/vet/VetRepository.java#L38-L46): repositório mínimo com cache.

```java
public interface VetRepository extends Repository<Vet, Integer> {

	@Transactional(readOnly = true)
	@Cacheable("vets")
	Collection<Vet> findAll() throws DataAccessException;
```

`@Cacheable("vets")` guarda o resultado depois da primeira chamada, e o cache é criado em [CacheConfiguration.java](../../src/main/java/org/springframework/samples/petclinic/system/CacheConfiguration.java#L35-L38). O card 0 do painel (botão "Inspecionar genéricos em tempo de execução") mostra, em execução, que `JpaRepository<Owner, Integer>` é resolvido pelo Spring e que a classe real do `VetRepository` é um proxy gerado.

## Esquema SQL

Cada banco tem o seu `schema.sql` em `src/main/resources/db/`. Trecho do PostgreSQL ([schema.sql](../../src/main/resources/db/postgres/schema.sql)):

```sql
CREATE TABLE IF NOT EXISTS types (
  id   INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name TEXT
);

CREATE TABLE IF NOT EXISTS owners (
  id         INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  first_name TEXT,
  last_name  TEXT,
  address    TEXT,
  city       TEXT,
  telephone  TEXT
);
CREATE INDEX IF NOT EXISTS idx_owners_last_name ON owners (last_name);
```

`IF NOT EXISTS` torna o script idempotente: ele roda a cada subida (`spring.sql.init.mode=always`) sem apagar os dados do Neon.

A estratégia `PhysicalNamingStrategySnakeCaseImpl` (em `application.properties`) converte `firstName` em `first_name` sem precisar de `@Column(name=...)` em cada campo.

## Vendo o SQL que o Hibernate gera

O card 7 do painel mostra o SQL real de cada chamada de repositório. Quem captura é o [SqlRecorder.java](../../src/main/java/org/springframework/samples/petclinic/dashboard/SqlRecorder.java#L33-L66), um `StatementInspector` do Hibernate:

```java
@Component
class SqlRecorder implements StatementInspector, HibernatePropertiesCustomizer {

	private static final ThreadLocal<List<String>> RECORDING = new ThreadLocal<>();

	@Override
	public void customize(Map<String, Object> hibernateProperties) {
		hibernateProperties.put(AvailableSettings.STATEMENT_INSPECTOR, this);
	}

	@Override
	public String inspect(String sql) {
		List<String> statements = RECORDING.get();
		if (statements != null) {
			statements.add(sql);
		}
		return sql;
	}

	<T> Recorded<T> record(Supplier<T> action) {
		List<String> statements = new ArrayList<>();
		RECORDING.set(statements);
		long start = System.nanoTime();
		try {
			T result = action.get();
			return new Recorded<>(result, List.copyOf(statements), (System.nanoTime() - start) / 1_000_000);
		}
		finally {
			RECORDING.remove();
		}
	}

}
```

- O Hibernate chama `inspect` antes de enviar cada comando ao banco.
- O `ThreadLocal` faz cada requisição gravar só o próprio SQL, mesmo com várias pessoas usando o painel ao mesmo tempo.
- `HibernatePropertiesCustomizer` registra o inspetor sem mexer em `application.properties`.

As demonstrações ficam em [DatabaseDemoController.java](../../src/main/java/org/springframework/samples/petclinic/dashboard/DatabaseDemoController.java#L79-L99):

```java
@GetMapping("/api/dashboard/sql")
ResponseEntity<QueryDemo> sql(@RequestParam String demo) {
	return switch (demo) {
		case "findById" -> ResponseEntity.ok(run(demo, () -> this.owners.findById(1).stream().toList()));
		case "findByLastName" -> ResponseEntity.ok(run(demo,
				() -> this.owners.findByLastNameStartingWith("Davis", PageRequest.of(0, 5)).getContent()));
		case "query" -> ResponseEntity.ok(run(demo, this.petTypes::findPetTypes));
		case "rollback" -> ResponseEntity.ok(run(demo, this::insertAndRollBack));
		default -> ResponseEntity.badRequest().build();
	};
}

private List<?> insertAndRollBack() {
	return this.transactions.execute(status -> {
		PetType type = new PetType();
		type.setName("demo-rollback");
		PetType saved = this.petTypes.saveAndFlush(type);
		status.setRollbackOnly();
		return List.of(saved);
	});
}
```

| Demo | O que mostra |
|---|---|
| `findById` | `select ... from owners ... where id=?` e o `EAGER` trazendo pets e visitas |
| `findByLastName` | o `LIKE` gerado a partir do nome do método, com paginação |
| `query` | a JPQL do `@Query` traduzida para SQL |
| `rollback` | um `INSERT` real que recebe id e é desfeito pela transação, sem deixar linha no banco |

O `switch` só aceita esses quatro nomes. Qualquer outro valor devolve 400, então não há como injetar SQL pelo parâmetro.
